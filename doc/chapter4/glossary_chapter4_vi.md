# Từ vựng ISTQB Chương 4 (Tiếng Việt)

Bảng này giúp bạn tra cứu nhanh từng thuật ngữ và nghĩa của nó.

| Thuật ngữ | Nghĩa |
|---|---|
| Test technique | Một phương pháp dùng để suy ra test case và xác định cần kiểm thử cái gì. |
| Black-box testing | Kiểm thử dựa trên hành vi mong đợi của hệ thống mà không cần biết mã bên trong. |
| Equivalence partitioning | Chia dữ liệu đầu vào thành các nhóm mà nên được xử lý giống nhau. |
| Boundary value analysis | Kiểm thử các giá trị ở rìa của phạm vi hợp lệ hoặc không hợp lệ. |
| Decision table testing | Kiểm thử các tổ hợp điều kiện và hành động tương ứng. |
| State transition testing | Kiểm thử cách hệ thống hoạt động khi chuyển từ trạng thái này sang trạng thái khác. |
| White-box testing | Kiểm thử dựa trên cấu trúc bên trong, logic hoặc mã nguồn của phần mềm. |
| Statement coverage | Tỷ lệ các câu lệnh có thể thực thi được chạy bởi test. |
| Branch coverage | Tỷ lệ các nhánh quyết định được thực hiện. |
| Experience-based testing | Các kỹ thuật kiểm thử dựa trên kiến thức, trực giác và kinh nghiệm của tester. |
| Error guessing | Dự đoán các defect có khả năng xảy ra dựa trên kinh nghiệm. |
| Exploratory testing | Học và kiểm thử cùng lúc, thường không theo kế hoạch được viết sẵn đầy đủ. |
| Checklist-based testing | Dùng checklist các điểm quan trọng để hướng dẫn testing. |
| Collaboration-based approach | Cách kiểm thử cần sự tham gia của đại diện nghiệp vụ, developer và tester cùng nhau. |
| User story | Mô tả ngắn về tính năng từ góc nhìn người dùng. |
| Acceptance criteria | Các điều kiện mà tính năng phải đáp ứng để được các bên liên quan chấp nhận. |
| ATDD | Viết acceptance test trước khi triển khai tính năng. |

## Mẹo ghi nhớ nhanh

Black-box = kiểm thử cái hệ thống làm được. White-box = kiểm thử cách hệ thống được xây dựng bên trong.
