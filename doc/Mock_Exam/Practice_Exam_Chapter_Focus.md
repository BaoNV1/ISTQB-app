## Set 1 – Fundamentals & Principles (10 questions)

### Question 1
Why is it impossible for testing to prove that a system is defect-free?

A. Because testers are not skilled enough  
B. Because exhaustive testing is usually impossible and testing can only show presence of defects  
C. Because tools always miss defects  
D. Because requirements are never written  

**Answer:** B

### Question 2
Defect clustering means:

A. Defects are evenly distributed  
B. A small number of modules often contain most defects  
C. All defects are found in the first test cycle  
D. Defects only appear in production  

**Answer:** B

### Question 3
Which principle advises that tests should be redesigned over time?

A. Early testing  
B. Pesticide paradox  
C. Absence-of-defects fallacy  
D. Testing is context dependent  

**Answer:** B

### Question 4
Root cause analysis is mainly used to:

A. Count the number of test cases  
B. Prevent similar defects in the future  
C. Replace regression testing  
D. Measure code coverage only  

**Answer:** B

### Question 5
Validation is primarily concerned with:

A. “Are we building the product right?”  
B. “Are we building the right product?”  
C. Only code style  
D. Only compiler warnings  

**Answer:** B

### Question 6
Verification is primarily concerned with:

A. “Are we building the right product?”  
B. “Are we building the product right?”  
C. Only user satisfaction surveys  
D. Only marketing claims  

**Answer:** B

### Question 7
Which of the following is a typical test objective?

A. To fix production incidents directly  
B. To provide information for decision making  
C. To write the requirements  
D. To manage the project budget  

**Answer:** B

### Question 8
Context-driven testing emphasises that:

A. One best practice fits every project  
B. Practices should be chosen according to the project context  
C. Only formal techniques are allowed  
D. Tools decide the test strategy  

**Answer:** B

### Question 9
Which activity is part of test monitoring and control?

A. Writing new user stories  
B. Comparing actual progress against the plan and taking corrective action  
C. Designing the database schema  
D. Only closing the project  

**Answer:** B

### Question 10
A good defect report should allow the reader to:

A. Guess what happened  
B. Understand and preferably reproduce the problem  
C. See only the severity rating  
D. Ignore the actual result  

**Answer:** B

## Set 2 – Test Techniques (10 questions)

### Question 1
In equivalence partitioning, an invalid partition contains:

A. Values that should be accepted  
B. Values that should be rejected or cause an error  
C. Only boundary values  
D. Only zero  

**Answer:** B

### Question 2
For an input field that accepts integers 1–100 inclusive, which are good boundary values?

A. 0, 1, 100, 101  
B. 50 only  
C. −1000 only  
D. 2 and 99 only  

**Answer:** A

### Question 3
Decision tables are most helpful when:

A. There is only one simple condition  
B. Multiple conditions combine to produce different actions  
C. Testing only the user interface colours  
D. Measuring memory usage  

**Answer:** B

### Question 4
In state transition testing, a “switch” coverage usually means:

A. Every state is visited  
B. Every transition is exercised at least once  
C. Only the start state is tested  
D. Only invalid transitions are tested  

**Answer:** B

### Question 5
Use-case testing derives tests from:

A. Compiler warnings  
B. Interactions between actors and the system  
C. Only database indexes  
D. Random input generation  

**Answer:** B

### Question 6
Statement coverage of 100% means:

A. All defects have been found  
B. Every executable statement has been executed at least once  
C. All branches have been taken  
D. The system is ready for release  

**Answer:** B

### Question 7
Branch (decision) coverage requires:

A. Only executing every statement  
B. Exercising both true and false outcomes of decisions  
C. Only testing the main success path  
D. Ignoring conditional logic  

**Answer:** B

### Question 8
Error guessing relies on:

A. Formal models only  
B. The tester’s knowledge of typical mistakes  
C. Random number generators only  
D. Only automated tools  

**Answer:** B

### Question 9
Exploratory testing is characterised by:

A. Completely unscripted chaos with no goals  
B. Simultaneous learning, test design, and execution, often time-boxed  
C. Only following pre-written scripts  
D. Only automated checks  

**Answer:** B

### Question 10
Which technique is black-box?

A. Statement coverage  
B. Decision coverage  
C. Equivalence partitioning  
D. Mutation testing  

**Answer:** C

## Set 3 – Test Management & Tools (10 questions)

### Question 1
A test strategy mainly describes:

A. The detailed daily schedule of one tester  
B. The overall approach to testing for a programme or organisation  
C. Only the list of open defects  
D. The source code structure  

**Answer:** B

### Question 2
Which is a product risk?

A. A key tester resigns  
B. The system may fail to meet a critical performance requirement  
C. The test environment is delivered late  
D. The budget is cut  

**Answer:** B

### Question 3
Which is a project risk?

A. Incorrect interest calculation  
B. Late delivery of the test environment  
C. A security vulnerability in production  
D. Poor usability of a screen  

**Answer:** B

### Question 4
Traceability between requirements and tests helps:

A. Only increase documentation volume  
B. Assess coverage and perform impact analysis when requirements change  
C. Remove the need for reviews  
D. Replace risk analysis  

**Answer:** B

### Question 5
Configuration management is important for testing because:

A. It prevents any code changes  
B. It ensures consistent versions of code, tests, and environments  
C. It replaces defect management  
D. It is only used by developers  

**Answer:** B

### Question 6
Which tool supports test execution and logging?

A. A word processor only  
B. A test execution / test management tool  
C. A pure graphics editor  
D. A compiler only  

**Answer:** B

### Question 7
A major risk of heavy automation is:

A. Tests running too quickly  
B. Brittle scripts and high maintenance cost when the UI changes  
C. Too much exploratory testing  
D. Finding too many defects  

**Answer:** B

### Question 8
In Agile teams, regression testing is often supported by:

A. Never running old tests  
B. Automated regression packs run in CI  
C. Only manual testing at the end of the release  
D. Ignoring previous functionality  

**Answer:** B

### Question 9
Exit criteria should be defined:

A. Only after testing is finished  
B. During planning, before major test execution starts  
C. Only by the customer after release  
D. Randomly each day  

**Answer:** B

### Question 10
Which metric indicates test case effectiveness?

A. Number of meetings  
B. Defects found by a test set versus total defects  
C. Lines of code written by testers  
D. Number of tools purchased  

**Answer:** B
