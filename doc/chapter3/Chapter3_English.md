# Chapter 3: Static Testing

Static testing is the review of work products without executing the software. It focuses on early defect detection, reducing costs, and improving the quality of requirements, design artifacts, and code.

## Static Testing Overview

- Static testing examines work products such as requirements, design documents, code, and test cases.
- It does not require running the application.
- Static testing is useful for early defect detection and can find issues before dynamic testing begins.

## Review Activities

- Informal review: quick, less structured review with few formal rules.
- Walkthrough: the author explains the product to a group for feedback.
- Technical review: a review focused on technical quality and correctness.
- Inspection: a formal review process with defined roles, rules, and documented findings.

## Roles in Reviews

- Author: creates the work product.
- Reviewer: examines the work product for defects.
- Moderator: coordinates the review process.
- Scribe: records issues, findings, and decisions.

## Benefits of Static Testing

- Better quality through early review and feedback.
- Lower cost by finding defects before they are embedded in later stages.
- Improved documentation and team alignment.

## Static vs Dynamic Testing

- Static testing checks the product without execution.
- Dynamic testing executes the software to validate behavior.
- Both approaches complement each other for a full quality strategy.
