# ISTQB CTFL v4.0.1 – Chapter 1 Quiz
## Fundamentals of Testing

---

### Question 1
Which of the following is a typical test objective?

A. Fixing defects found during testing  
B. Finding defects  
C. Writing production code  
D. Managing the project schedule  

**Answer:** B  
**Explanation:**  
One of the main objectives of testing is to find defects. Fixing defects is part of debugging (usually done by developers), not testing.

---

### Question 2
What is the main difference between testing and debugging?

A. Testing is done by developers, debugging is done by testers  
B. Testing finds defects, debugging finds the root cause and fixes them  
C. Testing and debugging are the same activity  
D. Debugging is only performed during static testing  

**Answer:** B  
**Explanation:**  
Testing aims to find defects and failures. Debugging is the process of finding the root cause of a defect and fixing it.

---

### Question 3
Which of the following best describes the relationship between testing and quality assurance (QA)?

A. Testing and QA are the same thing  
B. Testing is process-oriented, QA is product-oriented  
C. Testing is a form of quality control (product-oriented), while QA is process-oriented  
D. QA is only performed after testing is completed  

**Answer:** C  
**Explanation:**  
Testing focuses on detecting defects in the product (quality control). QA focuses on improving processes to prevent defects.

---

### Question 4
A developer makes a mistake while writing code. This mistake is called:

A. Failure  
B. Defect  
C. Error  
D. Root cause  

**Answer:** C  
**Explanation:**  
An **error** is a human mistake. This error may lead to a **defect** in the code. When the defective code is executed, it may cause a **failure**.

---

### Question 5
When the system produces an incorrect result during execution, this is called:

A. Error  
B. Defect  
C. Failure  
D. Root cause  

**Answer:** C  
**Explanation:**  
A **failure** is the observable incorrect behavior of the system when it is executed.

---

### Question 6
Which testing principle states that “Testing can show the presence of defects, but cannot prove their absence”?

A. Exhaustive testing is impossible  
B. Testing shows the presence of defects, not their absence  
C. Early testing saves time and money  
D. Defects cluster together  

**Answer:** B  
**Explanation:**  
This is the first testing principle. Even if many tests pass, it does not prove that the system is completely free of defects.

---

### Question 7
Which principle explains why we should not rely only on the same set of test cases repeatedly?

A. Testing is context dependent  
B. Absence-of-errors is a fallacy  
C. Tests wear out (Pesticide Paradox)  
D. Defects cluster together  

**Answer:** C  
**Explanation:**  
The Pesticide Paradox states that if the same tests are repeated over and over, they will eventually stop finding new defects. Test cases need to be reviewed and updated.

---

### Question 8
According to the testing principles, why is early testing important?

A. Because it is easier to write test cases early  
B. Because defects found early are cheaper to fix  
C. Because testers have more free time at the beginning of the project  
D. Because management requires early test reports  

**Answer:** B  
**Explanation:**  
The principle “Early testing saves time and money” is based on the fact that the cost of fixing a defect increases significantly the later it is found.

---

### Question 9
Which of the following is NOT one of the seven testing principles?

A. Exhaustive testing is impossible  
B. Testing is context dependent  
C. Testing can prove that the software is correct  
D. Defects cluster together  

**Answer:** C  
**Explanation:**  
Testing cannot prove that software is correct (absence of defects). This is the opposite of the first principle.

---

### Question 10
Which of the following is the correct order of the main test activities?

A. Test Execution → Test Design → Test Planning → Test Completion  
B. Test Planning → Test Analysis → Test Design → Test Implementation → Test Execution → Test Completion  
C. Test Design → Test Planning → Test Execution → Test Analysis  
D. Test Implementation → Test Planning → Test Execution → Test Monitoring  

**Answer:** B  
**Explanation:**  
The main test activities (in logical order) are:  
Test Planning → Test Monitoring & Control → Test Analysis → Test Design → Test Implementation → Test Execution → Test Completion.

---

### Question 11
What is “testware”?

A. Only the test cases  
B. Only the test tools  
C. All artifacts produced during the testing process  
D. Only defect reports  

**Answer:** C  
**Explanation:**  
Testware includes all work products created during testing such as test plans, test cases, test data, test scripts, defect reports, test reports, etc.

---

### Question 12
Why is maintaining traceability between the test basis and testware valuable?

A. It helps to increase the number of test cases  
B. It supports impact analysis, coverage measurement, and change management  
C. It is only required for safety-critical systems  
D. It reduces the need for test documentation  

**Answer:** B  
**Explanation:**  
Traceability allows us to see which requirements are covered by which test cases, analyze the impact of changes, and measure coverage.

---

### Question 13
What is the main advantage of the Whole Team Approach?

A. Only testers are responsible for quality  
B. Better collaboration and shared ownership of quality  
C. Testers work completely independently from developers  
D. Testing can be skipped in some iterations  

**Answer:** B  
**Explanation:**  
In the Whole Team Approach, everyone shares responsibility for quality, which improves collaboration and allows earlier feedback.

---

### Question 14
What is a benefit of independence of testing?

A. Testers and developers always work in the same room  
B. Testers may have a different and more objective viewpoint  
C. It always reduces communication problems  
D. It eliminates the need for developers to test their own code  

**Answer:** B  
**Explanation:**  
Independent testers can provide a different perspective and are often more objective when evaluating the system.

---

### Question 15
A small number of modules contain most of the defects found. This situation illustrates which testing principle?

A. Testing shows the presence of defects, not their absence  
B. Exhaustive testing is impossible  
C. Defects cluster together  
D. Testing is context dependent  

**Answer:** C  
**Explanation:**  
This is the “Defects cluster together” principle (related to the Pareto principle).

---

### Question 16
Which of the following is an example of a root cause?

A. The system crashed when the user entered invalid data  
B. A missing validation check in the code  
C. The developer did not understand the requirement correctly  
D. The test case failed  

**Answer:** C  
**Explanation:**  
The root cause is the fundamental reason why the defect was introduced (e.g., misunderstanding of the requirement).

---

### Question 17
According to the syllabus, which of the following is a generic skill required for testing?

A. Ability to write production code only  
B. Analytical thinking and attention to detail  
C. Ability to manage the project budget  
D. Ability to design the system architecture  

**Answer:** B  
**Explanation:**  
Important generic skills for testers include analytical thinking, communication, curiosity, and attention to detail.

---

### Question 18
“Absence-of-errors is a fallacy” means:

A. Finding no defects means the system is perfect  
B. Finding and fixing defects does not help if the system does not fulfill user needs  
C. Testers should stop testing when no more defects are found  
D. All defects must be fixed before release  

**Answer:** B  
**Explanation:**  
Even if the system has no defects, it may still be unsuccessful if it does not meet the real needs of the users.

### Question 22
Why is traceability useful in testing?

A. It removes the need for expected results
B. It links requirements to test cases and results
C. It guarantees defect-free software
D. It prevents all requirement changes

**Answer:** B  
**Explanation:** Traceability helps measure coverage and assess the impact of changes.

---

### Question 23
What does the absence-of-errors fallacy mean?

A. A system with few known defects is automatically useful
B. Removing defects does not guarantee that the system meets user needs
C. Errors can only occur in requirements
D. Testing should stop after the first failure

**Answer:** B  
**Explanation:** Software can contain few defects and still fail to satisfy user needs or business goals.

---

### Question 24
Which testing principle explains why complete testing of all combinations is usually impractical?

A. Exhaustive testing is impossible
B. Defects cluster together
C. Tests wear out
D. Testing is context dependent

**Answer:** A  
**Explanation:** The number of possible inputs and paths is normally too large for exhaustive testing.

---

### Question 25
What is a failure?

A. A human mistake
B. An incorrect behavior observed during execution
C. The reason a defect was introduced
D. A test plan activity

**Answer:** B  
**Explanation:** A failure is an observable deviation of the software from its expected behavior.

---

### Question 26
Which approach gives developers and testers shared responsibility for quality?

A. Whole Team Approach
B. Big Bang integration
C. Code freezing
D. Production-only testing

**Answer:** A  
**Explanation:** The Whole Team Approach promotes collaboration and shared ownership of product quality.

### Question 27
What is one benefit of testing early in the lifecycle?

A. Defects are cheaper to fix
B. No test planning is needed
C. Testers can ignore requirements
D. Testing becomes exhaustive

**Answer:** A  
**Explanation:** Earlier feedback reduces the cost and effort of correcting defects.

### Question 28
Which statement about independent testing is correct?

A. It removes the need for developer testing
B. It can provide a different perspective on the product
C. It prevents collaboration
