# ISTQB CTFL v4.0.1 – Chapter 1 Practice Quiz 1
## Fundamentals of Testing

**Inspired by official sample-exam patterns — original practice questions only**

---

### Question 1
Which statement describes a **valid** test objective?

A. To prove that there are no remaining defects in the system  
B. To prove that production will never experience failures  
C. To reduce the risk level of the test object and build confidence in quality  
D. To verify that every possible input combination has been tested  

**Answer:** C  
**Explanation:** Testing reduces risk and builds confidence. It cannot prove absence of all defects or that production will never fail; exhaustive testing is impossible (FL-1.1.1, principles 1 and 2).

---

### Question 2
Which example best shows testing activities that contribute to project success?

A. Testers avoid developers during coding so developers are not interrupted  
B. Testers are involved in several SDLC activities and help detect defects in work products early  
C. Only certified testers are allowed to design tests  
D. End users write all component-level defect reports  

**Answer:** B  
**Explanation:** Early tester involvement increases understanding and finds defects early (FL-1.2.1).

---

### Question 3
For several iterations the same regression tests are run unchanged and no new defects appear. Management is satisfied; you are skeptical. Which principle explains your concern?

A. Absence-of-defects fallacy  
B. Defects cluster together  
C. Tests wear out  
D. Exhaustive testing is impossible  

**Answer:** C  
**Explanation:** Repeating the same tests eventually finds fewer new defects; suites should be reviewed and updated (FL-1.3.1).

---

### Question 4
In the current iteration the team will implement payment. Which activity is part of **test analysis**?

A. Estimating that payment-service integration testing will take 8 person-days  
B. Deciding that the team should test whether payment can be split among multiple users  
C. Using BVA to derive amounts for minimum payment test cases  
D. Comparing actual vs expected results after a credit-card payment test and logging a defect  

**Answer:** B  
**Explanation:** Defining what should be tested (test conditions) is test analysis. Estimating is planning; BVA derivation is design; logging failures is execution (FL-1.4.1).

---

### Question 5
Which factors typically have a **significant** influence on the test approach?

A. Only the number of defects found in previous projects  
B. The SDLC, identified product risks, and regulatory requirements  
C. Only the physical layout of the test lab  
D. Only the color scheme of the UI  

**Answer:** B  
**Explanation:** SDLC, product risks, and regulations strongly shape the approach (FL-1.4.2).

---

### Question 6
Which task belongs MAINLY to a **testing** role?

A. Maintain the product backlog  
B. Design product solutions for new requirements  
C. Analyze the test basis  
D. Create the overall project budget alone  

**Answer:** C  
**Explanation:** Analyzing the test basis is a core testing-role task. Backlog is product owner; solution design is development; overall budget is management (FL-1.4.5).

### Question 7
Which skills are among the **most important** for a tester?

A. Creating the product vision and organizing the whole team’s schedule  
B. Domain knowledge, being a good team player, and critical thinking  
C. Only graphic design  
D. Only writing production deployment scripts  

**Answer:** B  
**Explanation:** Domain knowledge, teamwork, and critical thinking are key tester skills (FL-1.5.1).

### Question 8
How is the whole-team approach reflected between testers and business representatives?

A. Business representatives alone decide all automation tools  
B. Business representatives are excluded from quality discussions  
C. Testers help business representatives create suitable acceptance tests  
D. Testers never talk to business representatives  

**Answer:** C  
**Explanation:** Collaboration on acceptance tests is a classic whole-team advantage (FL-1.5.2).

---

### Question 9
What is the main difference between testing and debugging?

A. They are identical activities  
B. Testing finds defects/failures; debugging locates and removes the causes of defects  
C. Debugging is only done by end users  
D. Testing always fixes the code automatically  

**Answer:** B  
**Explanation:** Testing detects; debugging diagnoses and fixes (FL-1.1.2).

---

### Question 10
A programmer is distracted and writes an incorrect condition. The wrong condition is in the source code. When the system runs, users see incorrect totals. Match the terms:

A. Error = wrong totals; Defect = distraction; Failure = wrong condition  
B. Error = distraction/mistake; Defect = wrong condition in code; Failure = incorrect totals at runtime  
C. Error = incorrect totals; Defect = failure; Failure = root cause  
D. All three terms mean the same thing  

**Answer:** B  
**Explanation:** Error (human mistake) → defect (fault in work product) → failure (incorrect runtime behavior) (FL-1.2.3).

---

### Question 11
“Finding and fixing many defects guarantees the product will succeed in the market.” This belief is known as:

A. Tests wear out  
B. Exhaustive testing is impossible  
C. Absence-of-defects fallacy  
D. Defect clustering  

**Answer:** C  
**Explanation:** Even a low-defect product can fail if it does not meet user needs (principle 7).

---

### Question 12
Why is maintaining traceability valuable?

A. It replaces the need for any test cases  
B. It supports coverage assessment, impact analysis, and focused regression selection  
C. It guarantees zero defects  
D. It is only used after release  

**Answer:** B  
**Explanation:** Traceability links requirements/risks to tests and results (FL-1.4.4).

---

### Question 13
Which is a benefit of independence of testing?

A. Testers always know the code better than authors  
B. An independent view can find defects the authors miss  
C. Communication with developers is never needed  
D. Independence always means external outsourcing  

**Answer:** B  
**Explanation:** Independence provides a different perspective and challenges assumptions (FL-1.5.3).

---

### Question 14
Quality assurance (QA) is best described as:

A. The same as dynamic test execution only  
B. Process-oriented activities aimed at preventing defects  
C. Only writing defect reports  
D. Only user acceptance testing  

**Answer:** B  
**Explanation:** QA focuses on processes; testing evaluates products (FL-1.2.2).

---

### Question 15
Early testing saves time and money mainly because:

A. Later testing is forbidden  
B. Defects found earlier are usually cheaper to fix  
C. Exhaustive testing becomes possible  
D. Automation is never needed  

**Answer:** B  
**Explanation:** Principle 3 — early testing reduces cost of defects (FL-1.3.1).
