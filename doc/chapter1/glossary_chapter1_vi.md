# Từ vựng ISTQB Chương 1 (Tiếng Việt)

Bảng này giúp bạn tra cứu nhanh từng thuật ngữ và nghĩa của nó.

| Thuật ngữ | Nghĩa |
|---|---|
| Acceptance criteria | Các điều kiện mà sản phẩm hoặc tính năng phải đáp ứng để được các bên liên quan chấp nhận. |
| Activity | Một nhiệm vụ hoặc bước trong quy trình kiểm thử. |
| Bug | Một khiếm khuyết trong phần mềm. |
| Business goal | Kết quả mong muốn của sản phẩm từ góc nhìn kinh doanh. |
| Confidence | Mức độ các bên liên quan tin tưởng vào chất lượng phần mềm. |
| Context | Môi trường hoặc tình huống nơi kiểm thử được thực hiện. |
| Coverage | Mức độ một cơ sở kiểm thử hoặc yêu cầu được thử nghiệm bao phủ. |
| Coverage item | Một mục cần được bao phủ bởi kiểm thử. |
| Debugging | Quá trình tìm ra, phân tích và sửa nguyên nhân gây ra lỗi. |
| Defect | Một sai sót trong thành phần hoặc sản phẩm làm việc có thể gây ra lỗi cho phần mềm. |
| Defect clustering | Xu hướng các lỗi xuất hiện ở một số ít khu vực. |
| Dynamic testing | Kiểm thử liên quan đến việc thực thi phần mềm. |
| Error | Một sai sót của con người dẫn đến tạo ra defect. |
| Evaluation | Quá trình đánh giá các sản phẩm làm việc hoặc chất lượng phần mềm. |
| Exhaustive testing | Kiểm thử tất cả các trường hợp có thể; thường không thực tế. |
| Failure | Hành vi không đúng của phần mềm khi thực thi. |
| Fault | Cũng là một cách gọi khác của defect. |
| Functional requirement | Yêu cầu mô tả phần hệ thống phải làm gì. |
| Governance | Khung và quy tắc dùng để điều phối và hướng dẫn công việc. |
| Independence of testing | Mức độ tách biệt giữa người tạo sản phẩm làm việc và người kiểm thử nó. |
| Iterative | Thực hiện theo chu kỳ lặp. |
| Legal requirement | Quy định hoặc luật mà phần mềm phải tuân thủ. |
| Lesson learned | Kiến thức hữu ích thu được sau khi hoàn thành công việc, để cải thiện trong tương lai. |
| Methodical | Thực hiện một cách có tổ chức và hệ thống. |
| Monitoring | Theo dõi tiến độ và so sánh với kế hoạch. |
| Objective | Một mục đích hoặc mục tiêu. |
| Operational environment | Môi trường thực tế nơi phần mềm được sử dụng. |
| Pareto principle | Ý tưởng rằng một số ít nguyên nhân thường tạo ra phần lớn hậu quả. |
| Prevention | Hành động ngăn ngừa vấn đề trước khi chúng xảy ra. |
| Product backlog | Danh sách các mục việc cần phát triển. |
| Project milestone | Một điểm quan trọng trong thời gian dự án. |
| Quality | Mức độ mà sản phẩm thỏa mãn yêu cầu và đáp ứng nhu cầu của các bên liên quan. |
| Quality assurance (QA) | Cách tiếp cận hướng quy trình, phòng ngừa để đảm bảo chất lượng. |
| Quality control | Cách tiếp cận hướng sản phẩm, khắc phục bao gồm kiểm thử. |
| Regression testing | Kiểm thử để xác nhận lỗi trước đó đã được sửa và không tạo lỗi mới. |
| Requirement | Một nhu cầu, kỳ vọng hoặc điều kiện mà phần mềm phải đáp ứng. |
| Risk | Khả năng xảy ra một sự kiện hoặc kết quả không mong muốn. |
| Root cause | Nguyên nhân nền tảng của một defect hoặc failure. |
| Root cause analysis | Quá trình xác định nguyên nhân chính của một vấn đề. |
| Stakeholder | Người hoặc nhóm quan tâm đến phần mềm và kết quả của nó. |
| Static testing | Kiểm thử không thực thi phần mềm, ví dụ như review và phân tích tĩnh. |
| System thinking | Xem xét toàn bộ hệ thống và cách các bộ phận tương tác với nhau. |
| Test analysis | Hoạt động nghiên cứu cơ sở kiểm thử và xác định các điều kiện kiểm thử. |
| Test basis | Thông tin nguồn dùng để suy ra test case, ví dụ yêu cầu và tài liệu thiết kế. |
| Test case | Một tập hợp giá trị đầu vào, điều kiện thực thi và kết quả mong đợi. |
| Test completion | Giai đoạn cuối của kiểm thử tại một mốc quan trọng hoặc bản phát hành. |
| Test condition | Một khía cạnh cụ thể của đối tượng kiểm thử có thể được kiểm thử. |
| Test control | Các hành động để đảm bảo mục tiêu kiểm thử được đáp ứng. |
| Test data | Dữ liệu dùng làm đầu vào cho kiểm thử. |
| Test design | Quá trình biến điều kiện kiểm thử thành test case và các sản phẩm kiểm thử liên quan. |
| Test environment | Phần cứng, phần mềm, mạng và công cụ cần thiết để chạy kiểm thử. |
| Test execution | Chạy các test và so sánh kết quả thực tế với kết quả mong đợi. |
| Test implementation | Chuẩn bị testware cần thiết cho thực thi kiểm thử. |
| Test log | Hồ sơ chi tiết về một lần chạy test. |
| Test monitoring | Đo lường tiến độ và so sánh với kế hoạch kiểm thử. |
| Test object | Sản phẩm làm việc đang được kiểm thử. |
| Test objective | Mục tiêu của kiểm thử trong một bối cảnh cụ thể. |
| Test planning | Xác định chiến lược, cách tiếp cận và phạm vi kiểm thử. |
| Test procedure | Chuỗi các bước để thực thi kiểm thử. |
| Test process | Tập hợp các hoạt động và nhiệm vụ kiểm thử để đạt mục tiêu kiểm thử. |
| Test result | Kết quả của việc thực hiện một test. |
| Test suite | Một nhóm các test case hoặc thủ tục kiểm thử. |
| Testware | Tất cả các sản phẩm làm việc được tạo ra trong quá trình kiểm thử, ví dụ test case, script, log. |
| Testing | Một tập hợp các hoạt động nhằm phát hiện defect và đánh giá chất lượng của sản phẩm phần mềm. |
| Traceability | Khả năng kết nối các phần tử của cơ sở kiểm thử, test case, kết quả và defect. |
| Validation | Kiểm tra xem phần mềm có đáp ứng nhu cầu và kỳ vọng của người dùng và các bên liên quan không. |
| Verification | Kiểm tra xem phần mềm có thỏa mãn các yêu cầu đã được chỉ định không. |
| Work product | Bất kỳ tài liệu hoặc sản phẩm nào được tạo ra trong vòng đời phần mềm, như yêu cầu, tài liệu thiết kế, code, hoặc test case. |

## Mẹo học nhanh

Hãy ghi nhớ theo 3 nhóm chính:
- Chất lượng và lỗi: quality, defect, failure, root cause
- Các hoạt động kiểm thử: planning, analysis, design, implementation, execution, completion
- Tư duy kiểm thử: verification, validation, traceability, independence
