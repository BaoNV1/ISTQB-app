# ISTQB Chapter 5 Glossary

This table gives you a quick overview of the key terms in Chapter 5.

| Term | Meaning |
|---|---|
| Test plan | A document that describes the approach, scope, resources, and schedule for testing. |
| Entry criteria | Conditions that must be satisfied before testing begins. |
| Exit criteria | Conditions that must be achieved before testing can be considered complete. |
| Estimation | Predicting the amount of effort, time, and resources needed for testing. |
| Test case prioritization | Deciding which tests should be executed first based on importance or risk. |
| Test pyramid | A model suggesting many small fast unit tests, fewer integration tests, and even fewer UI tests. |
| Testing quadrants | A model that classifies testing based on business-facing and technology-facing concerns. |
| Risk | The possibility of a negative event or outcome. |
| Project risk | A risk related to the project, such as schedule delay or resource shortage. |
| Product risk | A risk related to the quality or behavior of the product. |
| Risk likelihood | The chance that a risk will happen. |
| Risk impact | The severity of the consequences if the risk occurs. |
| Risk analysis | Reviewing risks to understand their likelihood and impact. |
| Risk control | Actions taken to reduce or manage risks. |
| Risk-based testing | Testing more thoroughly in areas with higher risk. |
| Test monitoring | Tracking progress and comparing actual results with the plan. |
| Test control | Taking action to keep testing aligned with objectives. |
| Test progress report | A report showing what has been tested, what remains, and current status. |
| Test completion report | A report created when testing is finished, summarizing results and remaining risks. |
| Configuration management | Controlling changes to work products and keeping versions organized. |
| Defect management | The process of reporting, tracking, and resolving defects. |
| Defect report | A document that describes a defect clearly and includes relevant details. |

## Quick memory tip

Plan first, then monitor, control, and report.
