# ISTQB CTFL v4.0.1 – Chapter 5 Practice Quiz 3
## Focus: Risk, Monitoring/Control, CM & Defect Reports

---

### Question 1
What is the main idea of risk-based testing?

A. Eliminate all product and project risks completely  
B. Select, prioritize, and manage test activities based on risk analysis and risk control  
C. Test only low-risk areas  
D. Avoid documenting risks  

**Answer:** B  
**Explanation:** Risk-based testing uses risk analysis and risk control to focus testing where it matters most.

---

### Question 2
Risk analysis in the syllabus consists of:

A. Only defect logging  
B. Risk identification and risk assessment  
C. Only writing the completion report  
D. Only tool installation  

**Answer:** B  
**Explanation:** Risk analysis = identification + assessment; risk control = mitigation + monitoring.

---

### Question 3
Which pair correctly matches risk type to example?

A. Product risk — tester resigns; Project risk — payment fails under load  
B. Project risk — environment not ready; Product risk — security vulnerability in the system  
C. Product risk — budget cut; Project risk — missing field validation  
D. Both are always the same  

**Answer:** B  
**Explanation:** Project risks affect project delivery; product risks affect product quality.

---

### Question 4
After product risk analysis, a high-risk module should typically receive:

A. Less testing than low-risk modules  
B. More thorough testing, higher priority, and appropriate techniques/skills  
C. No reviews  
D. Only informal ad-hoc checks with no planning  

**Answer:** B  
**Explanation:** Product risk analysis influences thoroughness, scope, and prioritization (FL-5.2.3 / 5.2.4).

---

### Question 5
Which is a product-risk mitigation action by testing?

A. Accepting every risk without discussion  
B. Performing reviews/static analysis and applying stronger coverage on the risky area  
C. Hiding metrics from stakeholders  
D. Removing exit criteria  

**Answer:** B  
**Explanation:** Mitigation actions include skilled testers, independence, reviews, techniques/coverage, relevant test types, and regression.

---

### Question 6
Test monitoring is primarily about:

A. Issuing corrective directives only  
B. Gathering information to assess progress against exit criteria and plan  
C. Writing user stories  
D. Configuring production servers  

**Answer:** B  
**Explanation:** Monitoring collects data used to assess progress and whether exit criteria are met.

---

### Question 7
Adding people because the test environment arrived late is best classified as:

A. Test analysis  
B. A test control directive  
C. Static testing  
D. Equivalence partitioning  

**Answer:** B  
**Explanation:** Control uses monitoring information for corrective actions such as adjusting schedule or adding resources.

---

### Question 8
Why does configuration management matter for testing?

A. It guarantees zero defects  
B. It ensures the correct versions are tested and results can be traced and reproduced  
C. It replaces test design  
D. It is only used after release  

**Answer:** B  
**Explanation:** CM supports testing with controlled versions, baselines, and traceability (FL-5.4.1).

---

### Question 9
Which set of fields is most essential for a useful defect report?

A. Steps to reproduce, expected result, actual result, environment, severity, priority  
B. Only the tester’s name  
C. Only a screenshot with no steps  
D. Only the word “failed”  

**Answer:** A  
**Explanation:** Syllabus emphasizes enough information to resolve the issue, including reproduction steps, expected/actual, environment, severity, and priority (FL-5.5.1).

---

### Question 10
Severity and priority in a defect report mean:

A. The same thing always  
B. Severity reflects impact on stakeholders/requirements; priority reflects order of fixing  
C. Priority is only for documentation defects  
D. Severity is assigned only by customers after release  

**Answer:** B  
**Explanation:** Severity = degree of impact; priority = urgency/order to fix — they can differ.

---

### Question 11
A test completion report is typically produced:

A. Only before any testing starts  
B. At project milestones when a test level or test project completes  
C. Instead of all progress reports  
D. Only for unit testing  

**Answer:** B  
**Explanation:** Test completion consolidates data, experience, and testware at milestones and includes a completion report.

---

### Question 12
Which statement about communicating test status is TRUE?

A. Status should never be shared with stakeholders  
B. Communication should be timely, accurate, and tailored to the audience  
C. Only developers need progress information  
D. Dashboards must not show failed tests  

**Answer:** B  
**Explanation:** Status can be shared via dashboards, reports, and meetings; content should fit the audience (FL-5.3.3).
