# ISTQB Chapter 2 Glossary

This table gives you a quick overview of the key terms in Chapter 2.

| Term | Meaning |
|---|---|
| SDLC | The full process used to build, test, release, and maintain software. |
| Test level | A stage in the testing process that focuses on a different scope of the system. |
| Component testing | Testing individual components or modules in isolation. |
| Integration testing | Testing how different components work together. |
| System testing | Testing the complete system as a whole. |
| Acceptance testing | Testing to confirm the system satisfies business needs and acceptance criteria. |
| Test type | A category of testing based on what aspect is being checked. |
| Functional testing | Testing whether the system behaves according to the specified requirements. |
| Non-functional testing | Testing performance, security, usability, compatibility, and reliability. |
| Black-box testing | Testing based on inputs and outputs without needing to know the internal code. |
| White-box testing | Testing based on the internal structure, logic, or code of the component. |
| Change-related testing | Testing performed after changes are made to the software. |
| Confirmation testing | Testing done after a defect is fixed to verify the issue is truly resolved. |
| Regression testing | Testing performed to ensure that existing functionality still works after changes. |
| Maintenance testing | Testing done after release when changes such as bug fixes or updates are made. |
| Waterfall | A sequential development approach where testing often happens in separate phases. |
| Agile | A flexible development approach where testing happens more continuously. |
| DevOps | A collaborative approach connecting development, testing, and operations. |
| Shift left | Moving testing earlier in the software lifecycle. |
| Test-first approach | Writing tests before implementing the feature. |
| TDD | Writing a test first, then implementing code to make it pass. |
| ATDD | Defining acceptance tests before building the feature. |
| Retrospective | A meeting to reflect on what happened and improve the process. |

## Quick memory tip

Remember this order: test levels → test types → confirmation/regression → maintenance.
